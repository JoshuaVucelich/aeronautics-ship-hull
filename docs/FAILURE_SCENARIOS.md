# Failure scenarios for parked groups

At 05:39:59 UTC on 11 Oct 2026, phase 7 parked three grabber sub-levels that were touching or jointed to airship `26edccc0` and left the airship itself in full physics. One step later Sable removed the airship for an extreme Y range. Group park (`docs/issues/group-park.md`) freezes and wakes a connected set together. This note is the next set of ways that set can still end up half live, deleted, or stuck, and what this build does about each one.

`ship_hull.safeMode` (default false) is the kill switch. While it is on, every parked ship is woken and `parkNow` refuses. `/shiphull safe-mode on` does that immediately and logs `[shiphull] anomaly: safe-mode on`. `/shiphull safe-mode off` clears that override and follows the config again. A missing mixin sets a separate forced flag. Off cannot clear it, and the reply stays `safe-mode=true forced=true`. Anomalies use the prefix `[shiphull] anomaly:`.

Parked mode is not written to the world. A ship that registers does so in FULL.

## What this build changes

| Scenario | What we do |
| --- | --- |
| Chunk unload, or only half the group loaded | Removing a member wakes the rest with `memberUnloaded` before the ship is dropped from the registry. Adds are queued and the groups rebuild once, at the physics step and again at the end of the tick, instead of once per ship. A parked partner of a new ship wakes in that pass (`memberLoaded`). A ship with no usable box links to ships within 128 blocks of its position, so a broken partner nearby cannot stay frozen alone. It links to every ship only when that position cannot be read. |
| Server crash or kill mid-park | Parked mode is not loaded. Startup logs that ships register in FULL. Each added body gets `pipeline.wakeUp`, so a Sable-saved sleep does not leave the body frozen. |
| Player logs in next to a parked group | Login wakes a parked or cheap ship whose voxel box, or logical pose when the voxels are not ready, contains the player within `wakeRadius`. An unreadable parked pose wakes the group as `unreadablePose`. |
| Group spans a chunk or region border | Linking uses the world bounding box, not the center, and a spatial hash of 32-block cells. A box that crosses cells is inserted into each cell it touches. |
| Ship docked or jointed to another ship | Joints still union the group. An unmapped dynamic partner keeps the group live (`unmappedJoint`). Pose guard does not teleport one jointed body. Near Sable's remove bounds the whole jointed group shifts by one shared Y offset, then its velocity is zeroed. A group taller than the keep range is stopped and not split. Other unsafe reasons only zero the group's velocity. Before the Rapier step, a jointed group is zeroed when linear speed passes `absurdSpeed` or angular speed passes `absurdAngular`. A group that is only touching is clamped on linear speed. The joint list is copied once per physics step, and mass merge reads that copy. Jointed ships do not cache mass. A joint whose world anchors are under one block apart, or whose hulls overlap, logs once. Those warn-once sets are capped and drop a ship when it is removed. |
| Bearing, drill, or harvester still running | The first non-empty contraption sample counts as moving, and so does a bearing angle with no previous sample. A later angle change above 0.05, or contraption motion, wakes the group (`contraption`). |
| Train, elevator, or belt touching a ship | A non-player entity whose motion is above 0.05 blocks/tick inside a parked hull, or a hull that has already been still for 10 ticks, wakes the group (`movingEntity`). Ships that share a 32-block cell share one entity query, and that result is reused for 4 ticks. Elevators that are contraptions use the contraption check. |
| Explosion or split during park | Any block edit on a parked ship wakes the group immediately (`blockChange`). `/shiphull explode` promotes that ship to REBUILDING and wakes parked partners before it calls `setBlock`. Edits inside that loop are only counted, so the wake does not re-add the Rapier body from inside Sable's `setBlock`. A null plot, or a sub-level that is gone at entry or after the loop, returns without reading user data. Sable's user-data tag starts null, so a split creates one before it stores the pending pieces. |
| Assemble or disassemble while parked | A new sub-level is `memberLoaded`. Removing one is `memberUnloaded`. Block edits use `blockChange`. |
| Ship crosses a dimension or a portal | A sub-level whose level is no longer this one is removed here, which wakes parked partners. A Sable remove-and-add across dimensions uses the same hooks. |
| TPS lag spike, huge physics step | Parked ships wake before the physics step when two ticks in a row are each at least `ship_hull.lagWakeMillis` apart (default 500, 0 disables). One GC pause does not wake. The first tick after startup is ignored. The log is at most once a second. |
| Sable bounds, NaN, or zero mass | Pose guard still restores a non-finite pose, an absurd angular speed, a jump-and-speed pair, or a box inside the remove margin. A teleport already inside that margin is not saved, and that refusal is logged once per ship. A parked ship with a missing, non-finite, or non-positive mass, or a bad center of mass, wakes (`badMass`) and cannot be parked. |
| Many ships, O(n²) touch tests | Touch tests run inside shared 32-block cells. Ships that do not share a cell are not compared. A usable box that would cover more than 64 cells is compared with each ship directly and is not unioned with all of them. A ship with a position but no usable box links only within 128 blocks. Four or more ships with no readable position log once, and those still link to every group. |
| Mixin target missing on a version mismatch | `aeronautics_ship_hull.mixins.json` is `required: false`, so Mixin logs the miss and the game continues. Startup loads each park and pose target (`SubLevelPhysicsSystem`, `ServerSubLevel`, `RapierPhysicsPipeline`, `RapierConstraintHandle`) and sets `safeModeForced` if that mixin did not apply. `/shiphull safe-mode off` cannot clear it. A target that simply has not been used yet is not treated as missing. The apply record lives outside the mixin package, because Mixin will not let game code load a class from that package. |

## What is still open

- The physics step that is already running when a player logs in, or when a contraption starts moving, is not replayed. The body is pinned for that step. A block edit and a member load or unload wake before the method returns.
- The long step that already happened is not undone. The lag check wakes ships before the next step.
- A portal or dimension change that does not remove the sub-level and does not change `getLevel()` is not visible here.
- A joint whose anchors are already a block apart can still push during the step that is running. The clamp zeros the group before the next step. Group park does not freeze one side of a pair that is still moving. Bad anchors are a setup failure, and they log once.
- An existing `aeronautics_ship_hull-common.toml` keeps keys it already has. `safeMode` and `lagWakeMillis` appear when they are absent. A file that already has `lagWakeMillis = 250` keeps 250; the two-consecutive rule still applies. A missing `configVersion` is version 1. Loading that file rewrites `absurdAngular` 40 to 80. Loading anything below version 3 turns `enabled` off and saves `configVersion` 3. A file that already says version 3 keeps its `enabled` value, and a file that already says version 2 keeps its `absurdAngular`, including 40, on the way to version 3.
- A belt with no moving item, and an elevator that is not a contraption and not a moving entity, does not wake the ship.
- A player login was not run headless. The login hook is the same proximity test as the end-of-tick player scan.
- A missing mixin target was not reproduced by deleting Sable. The dedicated server boot is the check that the real targets applied and safe-mode stayed off.
